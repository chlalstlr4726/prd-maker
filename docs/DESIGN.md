# DESIGN

> 화면을 만들 때 AI가 따르는 규칙. 프리셋 하나를 골라 맨 아래 "내 선택"에 적는다.

## 1. 원칙

- 랜딩페이지가 아니라 도구다. 입력하고 결과 보는 게 한 화면에서 끝난다.
- 주인공은 결과 카드다. 폼은 조용하게, 결과는 읽기 좋게.
- 장식 대신 여백과 위계로 정리한다: 제품명 > 섹션 라벨 > 본문.

## 2. 기술 규칙

- 스타일은 Tailwind만 쓴다 (create-next-app에 이미 들어 있음). shadcn, MUI 같은 UI 라이브러리는 오늘 추가하지 않는다.
- 색은 `app/globals.css`의 CSS 변수로만 정의하고, 컴포넌트에는 hex 값을 직접 쓰지 않는다.
- 변수 이름: `--bg`, `--card`, `--text`, `--muted`, `--border`, `--accent`
- 폰트는 create-next-app 기본값(Geist)을 유지한다. 한글이 어색하면 `next/font/google`의 `Noto_Sans_KR`로 바꿔도 된다.

## 4. 레이아웃

- 본문 최대 너비 672px (`max-w-2xl`), 가운데 정렬, 좌우 패딩 16px.
- 모바일 폭(375px)에서도 가로 스크롤이 생기면 안 된다.
- 헤더: 왼쪽에 서비스 이름 + 한 줄 설명, 오른쪽에 "내 PRD 목록" 링크.

## 5. 컴포넌트

### 입력 폼
- 입력칸은 전체 너비, placeholder에 예시를 넣는다. (예: "해커톤 팀원 매칭 서비스")
- 개발 기간은 select: 해커톤 24시간 / 1주 / 1달

### 주 버튼
- 전체 너비, `--accent` 또는 진한 배경.
- 로딩 중에는 비활성화하고 문구를 "PRD 작성 중... (10~30초)"로 바꾼다.

### 결과 카드 (`components/SpecView.tsx`)
- 헤더: 제품명(크게), 한 줄 요약, 오른쪽에 "마크다운 복사" 버튼.
- 섹션 순서: 문제 → 타깃 유저 → 핵심 기능 → 유저 플로우 → 화면 → 데이터 모델 / API → 이번에 안 하는 것 → 리스크 → 첫 프롬프트
- P0는 `--accent` 색 배지, P1은 회색 배지.
- 데이터 모델, API, 첫 프롬프트는 고정폭 폰트.

### 목록 아이템
- 카드 전체가 링크다.
- 윗줄: 개발 기간 · 생성 날짜 (작게, `--muted`)
- 제품명 (굵게), 한 줄 요약

## 6. 상태 (4개 다 처리)

| 상태 | 표시 |
|---|---|
| 로딩 | 버튼 비활성 + 문구 변경, 목록은 "불러오는 중..." |
| 빈 상태 | "아직 만든 PRD가 없다" + 메인으로 가는 링크 |
| 에러 | 빨간 박스에 서버가 준 `error` 메시지를 그대로 |
| 성공 | 결과 카드 |

## 7. 하지 말 것 (AI가 만든 티가 제일 많이 나는 것들)

- 이모지를 아이콘 대신 쓰기
- 보라-파랑 그라데이션 배경, 글래스모피즘
- 히어로 섹션, "Get Started" 같은 랜딩 문구
- 카드마다 그림자 진하게
