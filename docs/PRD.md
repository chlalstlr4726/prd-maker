# PRD: PRD 메이커

> 이 문서가 기준이다. AI(Claude Code / Codex)는 이 문서에 적힌 것만 만든다.
> 1~7번은 공통 뼈대라 그대로 두고, 8번 "내 버전"만 각자 채운다.

## 1. 한 줄 요약

아이디어 한 줄을 넣으면 AI가 해커톤에서 바로 쓸 수 있는 PRD(기능 우선순위, 화면, 데이터 모델, API, 바이브 코딩 첫 프롬프트)를 만들어 주고, 만든 PRD를 저장해 두었다가 다시 꺼내 쓰는 웹 서비스.

## 2. 문제

- 해커톤 첫 2~3시간을 기획 회의로 날린다. 범위를 크게 잡아서 데모 때는 반쯤 만든 걸 보여주게 된다.
- 바이브 코딩 툴에 "앱 만들어줘"라고 던지면 구조가 산으로 간다. 기능 우선순위, 화면, 데이터 구조가 정해진 문서가 먼저 있어야 AI도 제대로 만든다.
- 그런데 PRD를 처음부터 쓰는 건 귀찮고, 뭘 써야 하는지도 잘 모른다.

## 3. 타깃 유저

- 1차: 해커톤이나 팀 프로젝트를 앞둔 NEXT 학회원. 아이디어는 있는데 PRD로 정리해 본 적이 없거나 귀찮은 사람.
- 2차: 사이드 프로젝트를 시작하려는 대학생 개발자.

## 4. 핵심 기능

| 우선순위 | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| P0 | PRD 생성 | 아이디어 이름, 문제, 타깃(선택), 개발 기간을 입력하면 AI가 PRD를 만들어 화면에 보여준다 | 버튼을 누르고 30초 안에 결과 카드가 뜬다 |
| P0 | 자동 저장 | 생성된 PRD가 Supabase `specs` 테이블에 저장된다 | Supabase Table Editor에서 새 row가 보인다 |
| P0 | 목록 | `/specs`에서 내가 만든 PRD를 최신순으로 본다 | 새로고침해도 목록이 그대로 있다 |
| P1 | 마크다운 복사 | PRD 전체를 마크다운으로 클립보드에 복사한다 | 다른 레포의 `docs/PRD.md`에 붙여넣으면 제목과 섹션이 살아 있다 |
| P1 | 상세 / 삭제 | `/specs/[id]`에서 하나를 열어 보고 지울 수 있다 | 삭제 후 목록에서 사라진다 |
| P1 | 내 버전 기능 | 8번에서 고른 기능 | 8번에 적은 완료 기준 |

## 5. 유저 플로우

1. `/`에 들어온다.
2. 아이디어 이름, 해결하려는 문제, 타깃 유저(선택), 개발 기간(해커톤 24시간 / 1주 / 1달)을 입력한다.
3. "PRD 만들기"를 누르면 로딩 표시가 뜬다 (10~30초).
4. 결과 카드가 뜬다. 핵심 기능(P0/P1), 유저 플로우, 데이터 모델/API, 첫 프롬프트를 확인한다.
5. "마크다운 복사"로 가져가거나, "내 PRD 목록"으로 이동한다.
6. 목록에서 예전에 만든 PRD를 다시 연다.

## 6. 화면

| 경로 | 이름 | 역할 |
|---|---|---|
| `/` | 메인 | 입력 폼 + 생성 결과 카드 |
| `/specs` | 내 PRD 목록 | 저장된 PRD 카드 목록 |
| `/specs/[id]` | 상세 (P1) | PRD 하나 전체 보기 + 삭제 |

## 7. 이번에 안 만드는 것

- 로그인 / 회원가입: 각자 자기 Supabase를 쓰니까 필요 없다.
- 공유 링크, 실시간 협업, 결제
- 스트리밍 출력 (글자가 한 글자씩 나오는 것). 로딩 표시로 충분하다.
- 배포: 세션 이후 과제 (Vercel)
